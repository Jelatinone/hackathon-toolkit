# prepare-demo

## Purpose and triggers

Use for demo preparation/rehearsal; do not invent footage or ship features.

## Inputs and prerequisites

Required: verified build, audience, time budget, track criteria and core journey. Discover existing footage, claims and environments. Default: playbook timing suggestions only when event rules do not specify.

Resolve the host project root from the invoking adapter/user, not this file's repository. Read project instructions, [shared contract](../../../docs/PROJECT_CONTRACT.md), [formats](../../../docs/FORMATS.md), and relevant approved project records. Source guidance lives in this toolkit; project state stays in the host. If invoked directly without a clear host, resolve it before dependent work.

## Read and write boundaries

Read PLAN demo/proof sections, evidence and playbook sections 6–7. Write assigned demo notes/sections only; no application changes or publication.

## Workflow

1. Map each proposed claim to verified behavior and limitations for the exact build.
2. Prepare a timed script and proof scenes using the same core journey; distinguish live, recorded, mocked and future work.
3. Create shot list with owners and missing footage; label placeholders clearly.
4. Rehearse available actions in the permitted environment, record actual duration and failures, and define an honest fallback.
5. Report missing proof or recording rather than describing it as done.

## Outputs

Return the strict common report from FORMATS. Use the following H3 subsections inside Result, in order; retain them even for blocked outcomes. Do not create a report file unless a destination is assigned.

### Timed script

Scene timing, narration/action, audience and total budget.

### Claim/proof matrix

Claim, source evidence/revision, demonstration and limitations.

### Shot list

Scene, owner, footage path/status and missing capture.

### Rehearsal results

Actual duration/actions/results or explicitly not run.

### Fallback

Known-good route or recording, disclosure and failure trigger.

## Acceptance criteria

Claims are traceable, timing respects event rules, and unrecorded/unverified scenes remain explicit. All required report sections, metadata and verification rows are present; distinguish observations from assumptions.

## Failure and approval behavior

Missing build/proof prevents verified rehearsal claims. Recording, uploading or publishing occurs only within authorization; preparation alone grants none. Preserve prior explicit authorization and continue independent authorized work where possible. Missing prerequisites receive a concrete blocked/incomplete report, not fabricated success.
